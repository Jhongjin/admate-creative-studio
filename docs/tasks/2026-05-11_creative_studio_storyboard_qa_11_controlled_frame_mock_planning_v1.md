## Dummy And Sanitized Fixture Rules

Allowed dummy fixture text:

- generic product labels such as `Compass`, `Sentinel`, `Lens`, `Foresight`,
  and `Agent Core`
- generic labels from the scene-level dummy visual spec
- placeholders that are visibly non-operational, such as `Demo proof`,
  `Guide Source`, `Needs Review`, `Approval`, and `Hypothesis`
- safe example domains only when a URL-like label is required:
  `example.com`, `admate.ai.kr`, or `demo.admate.ai.kr`

Forbidden fixture content:

- real customer, advertiser, account, campaign, creative, audience, budget,
  billing, contract, audit, dashboard, log, DB, API, metric, performance,
  forecast, or operational data
- real names, emails, employee identities, reviewer identities, customer
  quotes, testimonials, private strategy, or personal data
- source media filenames, asset paths, signed URLs, storage paths, internal
  dashboard paths, raw provider outputs, or raw source payloads
- token, cookie, credential, secret, session, env value, API key, webhook, or
  private URL
- mock numbers that look like real performance, ROI, savings, budget, billing,
  conversion, delivery, or productivity claims

## Review Rubric

Use this rubric for future document-only mock planning review:

| Review area | Pass condition | Reject if |
| --- | --- | --- |
| Row baseline | Scene ID is frozen in QA 9 and matches the frame-spec table. | Row is new, renamed, merged, generated, or not frozen. |
| Fixture safety | Fixture is dummy, sanitized, abstract, and non-operational. | Fixture needs real data, source media, screenshots, or assets. |
| Label clarity | Required disclosure and safety cues are named before media work. | Labels are vague, decorative, or missing. |
| Presenter boundary | Presenter is virtual-guide only and follows the approved scene role. | Presenter appears as a real person, employee, customer, influencer, or testimonial. |
| Approval safety | Action-implying rows preserve human approval language. | The frame implies autonomous execution, blocking, publishing, approval, or training. |
| Performance safety | Forecast, ROI, savings, and impact rows preserve no-guarantee language. | The frame implies guaranteed performance or uses real metrics. |
| Data safety | No real operational, customer, dashboard, API, DB, log, billing, or audit data is needed. | Any real or real-looking private data is required. |
| Scope discipline | The plan stays text-only. | Any media, render, asset, code, vendor, model, or production action is included. |

Any rejected row remains blocked. Any row marked `NEEDS CLARIFICATION` may be
updated only through another document-only planning note.
