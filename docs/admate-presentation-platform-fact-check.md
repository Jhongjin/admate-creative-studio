# AdMate 발표자료 플랫폼별 Fact-check 반영표 v2

대상 문서: `docs/admate-presentation-strategy-and-script.md`
작성 목적: Commander가 취합한 플랫폼별 검증 의견을 v2 발표 문장에 어떻게 반영했는지 기록하고, 남은 재검증 질문을 정리한다.

## 1. v2 반영 원칙

v2의 기준 문장은 다음과 같다.

> AdMate는 판단을 대신하는 AI가 아니라, 판단 근거를 보존하고 통제 가능한 운영 확장을 돕는 AI Agent 플랫폼입니다.

전체 문서에서 다음 표현은 제거하거나 완화했다.

- 판단 자동 확정
- 성과 보장
- 최적 예산 추천
- 실시간/즉시/항상 감지
- 완전 자동 집행
- 승인 없는 실행
- 자동 학습 또는 즉시 기준 변경

## 2. 플랫폼별 반영 결과

| 영역 | v1 표현 방향 | v2 반영 방향 | 상태 |
|---|---|---|---|
| Compass | 정책/가이드 기준 정렬 | 정책·상품·심사 가이드 근거를 찾아 검토 범위를 좁히는 도구 | 반영, 최종 문장 재확인 필요 |
| Sentinel Monitoring | 위험 신호 선제 경고 | 운영 중/주기적 모니터링과 이상 징후 확인 흐름 | 반영, 감지 범위 재확인 필요 |
| Sentinel Prelaunch | Sentinel Media Mix | Sentinel Prelaunch의 미디어믹스 비교/사전 검수 기능 | 반영, 명칭 재확인 필요 |
| Lens | 재사용 가능한 evidence package | 검토와 보고에 활용할 수 있는 증빙 이미지와 캡처 정보 | 반영, 품질 기준 재확인 필요 |
| Foresight | 다음 판단 가설 | 예측과 벤치마크 결과를 다음 캠페인 계획의 검토 기준으로 활용 | 반영, 수치 사용 조건 재확인 필요 |
| Agent Core / Openclaw | 제품을 하나의 loop로 연결 | 메인에는 Agent Core 우선 표기, Openclaw는 내부 실행/자동화 흐름으로 설명 | 반영, 최종 표기 확인 필요 |
| Hermes | 학습/기억 흐름 | 운영자 피드백과 검증된 이벤트 기반 학습 후보, 승인된 기준 축적 | 반영, 용어 재확인 필요 |

## 3. Compass 재검증 질문

v2 사용 문장:

- "Compass는 광고 정책, 상품, 심사 가이드의 근거를 찾아 검토 범위를 좁히는 도구다."
- "Compass는 정책 판단을 자동 확정하지 않고, 사람이 볼 근거와 출처를 정리한다."

재검증 질문:

- "광고 정책, 상품, 심사 가이드" 세 범주를 모두 Compass 설명에 포함해도 되는가?
- "검토 범위를 좁힌다"는 표현이 실제 기능과 제품 방향에 맞는가?
- "근거와 출처를 정리한다"는 문장에서 source/citation 표현을 어느 수준까지 사용할 수 있는가?

금지 유지:

- 정책 판단 자동 확정
- 심사 통과 보장
- 정책 리스크 제거
- 모든 정책 완벽 반영

## 4. Sentinel Monitoring 재검증 질문

v2 사용 문장:

- "Sentinel Monitoring은 운영 중 또는 주기적 모니터링을 통해 이상 징후 확인 흐름을 만든다."
- "운영자가 봐야 할 위험 신호와 조치 필요 항목을 정리한다."

재검증 질문:

- "운영 중"과 "주기적 모니터링" 중 어떤 표현이 더 정확한가?
- "이상 징후"라는 용어를 써도 되는가, 아니면 "조치 필요 항목"처럼 더 중립적인 표현이 맞는가?
- "조치 필요 항목" 또는 "운영자가 검토할 항목" 중 어느 표현이 더 적합한가?

금지 유지:

- 실시간으로 항상 감지
- 즉시 감지
- 모든 위험 자동 발견
- 승인 없는 조치 실행

## 5. Sentinel Prelaunch Media Mix Review 재검증 질문

v2 사용 문장:

- "Sentinel Prelaunch의 미디어믹스 비교/사전 검수 기능"
- "Google/Meta 중심의 세팅 검수와 비교 흐름"

재검증 질문:

- 공식 명칭은 "Sentinel Prelaunch Media Mix Review"로 표기해도 되는가?
- "미디어믹스 비교"와 "사전 검수" 중 어느 표현이 더 정확한가?
- Google/Meta 중심이라고 명시하는 것이 현재 지원 범위와 맞는가?
- "세팅 검수"에 포함되는 항목을 발표자료에서 어디까지 말할 수 있는가?

금지 유지:

- Sentinel Media Mix라는 독립 제품명
- 최적 미디어믹스 추천
- 예산 배분 추천
- 모든 매체 지원

## 6. Lens 재검증 질문

v2 사용 문장:

- "Lens는 검토와 보고에 활용할 수 있는 증빙 이미지와 캡처 정보를 정리한다."
- "핵심 품질 기준은 캡처 성공 여부보다 결과 이미지가 실제 매체 지면처럼 보이는지다."

재검증 질문:

- "증빙 이미지와 캡처 정보"라는 표현이 Lens의 현재 산출물과 맞는가?
- "실제 매체 지면처럼 보이는지"를 품질 기준으로 발표해도 되는가?
- 실제 Lens 화면 대신 sanitized mock visual을 쓰는 방향이 맞는가?

금지 유지:

- 재사용 가능한 evidence package
- 모든 지면 완벽 재현
- 실제 광고주 화면 무제한 사용

## 7. Foresight 재검증 질문

v2 사용 문장:

- "Foresight는 예측과 벤치마크 결과를 다음 캠페인 계획의 검토 기준으로 활용한다."
- "수치와 차트는 sanitized mock 또는 익명화된 집계 예시로만 제시한다."

재검증 질문:

- "예측과 벤치마크"를 함께 말해도 되는가?
- "다음 캠페인 계획의 검토 기준"이라는 표현이 제품 방향과 맞는가?
- 발표자료에 사용할 수 있는 수치/차트의 조건은 sanitized mock과 익명화된 집계 예시 중 무엇인가?

금지 유지:

- 성과 보장
- 최적 예산 추천
- 정확한 예측
- 자동 의사결정

## 8. Agent Core / Openclaw 재검증 질문

v2 사용 문장:

- "Agent Core는 실행 요청, 승인, 기록이 추적되는 공통 레이어다."
- "Openclaw는 Agent Core 내부의 실행/자동화 흐름으로 설명한다."
- "승인 게이트와 audit trail을 중심으로 설명한다."

재검증 질문:

- 메인 슬라이드에서는 Agent Core만 우선 표기하고 Openclaw는 발표자 노트나 appendix에서 설명하는 방향이 맞는가?
- "공통 레이어"라는 표현이 아키텍처와 제품 메시지 양쪽에서 안전한가?
- "실행 요청, 승인, 기록"을 Agent Core 본문 bullet로 쓰고, "학습 후보"는 Hermes와 연결해 설명해도 되는가?
- audit trail 표현을 임원 보고용으로 사용해도 되는가?

금지 유지:

- 제품들을 완전한 loop로 연결 완료
- 완전 자동 집행
- 승인 없는 실행
- 모든 작업 자동 orchestration

## 9. Hermes 재검증 질문

v2 사용 문장:

- "Hermes는 운영자 피드백과 검증된 이벤트를 바탕으로 학습 후보를 만든다."
- "승인된 기준만 운영 지식으로 축적한다."

재검증 질문:

- "학습 후보"라는 표현이 Hermes의 역할과 맞는가?
- "검증된 이벤트"와 "운영자 피드백"을 입력으로 말해도 되는가?
- "승인된 기준만 운영 지식으로 축적"이라는 문장이 현재 설계 원칙과 맞는가?

금지 유지:

- 자동 학습
- 스스로 판단
- 즉시 기준 변경
- 검토 없는 운영 지식 반영

## 10. Commander 확인 필요 항목

- 10장 임원 보고용 구조를 v2 우선안으로 승인할지
- 본문에서 Google/Meta 중심 제한 파일럿을 명시해도 되는지
- 메인 슬라이드에서 "Agent Core"만 표기하고 Openclaw는 appendix 설명으로 제한하는 방향을 최종 승인할지
- Hermes를 메인 8장에 포함할지, Agent Core의 하위 운영 지식 흐름으로 설명할지
- sanitized mock과 익명화된 집계 예시 중 실제 제작 기준을 무엇으로 고정할지
