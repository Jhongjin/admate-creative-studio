# AdMate Knowledge & Operations Loop 요약

이 문서는 Commander가 발표자료와 인포그래픽 제작 전에 AdMate의 운영 구조를 빠르게 검토하기 위한 2-page 요약이다. 구현 완료 여부가 불확실한 항목은 후보 또는 future/planned로 분리해 표현한다.

## Page 1. 전체 순서도형 요약

**핵심 흐름**

업무 신호 -> 플랫폼 판단 근거 -> 조치/알림 -> 사용자 반응 -> Hermes 후보화 -> 사람 승인 -> 운영 지식 축적 -> 다음 운영 반영 -> 신규 실험 후보

1. **업무 신호 발생**
   - 기획 질문, 정책 확인 요청, 운영 이상 신호, 증빙 필요, 예측/벤치마크 필요가 업무 시작점이 된다.
   - DAT Workflow는 팀 메일과 업무 요청을 수집해 정규화, 분류, 담당자, 난이도, 이슈, 레퍼런스 후보를 만든다.
   - 이 단계의 결과는 확정 지식이 아니라 다음 판단을 돕는 입력값이다.

2. **플랫폼 판단 근거 생성**
   - Compass는 정책, 상품, 심사 가이드의 근거를 찾아 확인할 범위를 좁힌다.
   - Sentinel과 Openclaw는 운영 중 발생한 조치 필요 신호와 검토 기준을 action 후보로 정리한다.
   - Lens는 검토와 보고에 활용할 증빙 이미지와 캡처 정보를 정리하고, Foresight는 다음 계획을 검토할 예측/벤치마크 기준을 제공한다.

3. **조치와 알림 흐름**
   - Agent Core는 실행 요청, 권한, 승인, 기록이 같은 운영 기준 안에서 추적되도록 한다.
   - Openclaw/Sentinel 신호는 n8n/Slack 흐름을 통해 담당자에게 전달될 수 있다.
   - 알림은 자동 집행이 아니라 사람이 확인할 action 후보와 audit event를 남기는 구조로 표현한다.

4. **사용자 반응 회수**
   - 사용자는 승인, 수정, 무시, 추가 확인 요청, 레퍼런스 지정을 통해 플랫폼 판단 근거에 반응한다.
   - 이 반응은 다음 실행의 근거가 아니라 audit/action 기록과 learning candidate 또는 reference candidate로 남는다.
   - 레퍼런스 지정 항목은 추후 비딩, 전문성 설명, 유사 업무 대응 자료의 후보가 될 수 있다.

5. **Hermes 후보화와 승인 지식 축적**
   - Hermes는 자동 학습하지 않는다.
   - 승인 전 데이터는 knowledge가 아니라 learning candidate 또는 reference candidate다.
   - 사람이 승인한 기준, 레퍼런스, 운영 지식만 다음 업무에 재사용 가능한 approved knowledge로 축적된다.

6. **다음 운영과 장기 확장**
   - 승인된 운영 지식은 다음 기획, 검수, 증빙, 분석 과정에서 판단 기준을 다시 불러오는 데 쓰인다.
   - AdMate와 DAT Workflow에서 축적된 운영 지식은 AI Venture Lab의 신규 플랫폼 아이디어 후보로 연결될 수 있다.
   - AI 최신 뉴스 수집 신호는 future/planned input이며, 향후 사업성 검토, PRD/MVP, 실험, 실제 프로젝트화의 장기 루프로 연결한다.

| --- | --- | --- | --- |
| DAT Workflow | 팀 메일과 업무 요청을 수집해 업무를 정규화하고 분류한다. | 담당자, 난이도, 이슈, 레퍼런스 후보를 만든다. 사람 승인 전에는 확정 지식이 아니다. | 레퍼런스 지정 항목은 추후 비딩/전문성 자료 후보로 활용 가능하다. |

| Foresight | 예측과 벤치마크를 다음 계획의 검토 기준으로 제공한다. | 성과를 보장하거나 배분안을 확정하지 않고 검토 기준과 가설 후보를 제공한다. | 차트는 sanitized mock 또는 익명화 집계 예시를 기본값으로 둔다. |
| Agent Core | 권한, 승인, 기록, audit trail을 추적하는 공통 운영 레이어다. | 승인 없는 실행이나 완전 자동 집행으로 표현하지 않는다. | 제품 간 실행 요청과 승인 흐름의 연결 범위는 플랫폼 검증 결과에 맞춰 조정한다. |
| Hermes | 운영자 피드백과 검증된 이벤트를 learning/reference candidate로 정리한다. | 사람 승인 전에는 knowledge가 아니다. 승인된 기준만 운영 지식으로 축적한다. | 승인 지식이 쌓이면 다음 업무의 검토 기준, 레퍼런스, 운영 규칙으로 재사용된다. |
| AI Venture Lab | 축적된 운영 지식을 신규 플랫폼 아이디어 발굴의 입력으로 활용한다. | 아이디어는 바로 제품이 아니라 사업성 검토와 실험 후보로 다룬다. | AI 뉴스 수집 신호는 future/planned input이며 PRD/MVP, 실험, 프로젝트화로 이어진다. |

## 표현 구분

- **확정 표현**: AdMate는 판단을 대신하는 AI가 아니라 판단 근거, 승인, 기록, 재사용 가능한 운영 기준을 보존하는 구조다.
- **후보 표현**: 승인 전 사용자 반응, 레퍼런스 지정, Openclaw/Sentinel action, DAT 분류 결과는 learning candidate 또는 reference candidate다.
- **future/planned 표현**: AI 최신 뉴스 수집, AI Venture Lab 장기 루프, 일부 n8n/Slack 자동화 범위는 future/planned 또는 구현 확인 대상으로 둔다.

## 최종 확인 포인트

- n8n/Slack 알림이 실제로 어느 이벤트까지 연결되는지 플랫폼 담당 확인이 필요하다.
- DAT Workflow가 생성하는 담당자, 난이도, 이슈, 레퍼런스 후보의 현재 구현 범위 확인이 필요하다.
- AI Venture Lab과 AI 뉴스 수집은 현재 장기 확장 시나리오이며, 발표 본문에서는 future/planned로 표기한다.
