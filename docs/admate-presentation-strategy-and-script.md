# AdMate 발표자료 문서 v2

대상 repo: `D:\Projects\AdMate\admate-creative-studio`
문서 목적: Commander가 취합한 플랫폼별 검증 의견을 반영해, 임원 리뷰 가능한 AdMate 발표자료 v2 구조와 대본을 정리한다.

## 1. v2 메시지 원칙

AdMate의 중심 메시지는 다음 한 문장으로 정렬한다.

> AdMate는 판단을 대신하는 AI가 아니라, 판단 근거를 보존하고 통제 가능한 운영 확장을 돕는 AI Agent 플랫폼입니다.

v2에서는 제품 기능을 과장하지 않고, 임원 보고에서 바로 검토할 수 있는 운영 관점으로 재구성한다.

- AdMate가 해결하는 문제는 단순 업무량이 아니라, 판단 기준이 조직에 남지 않는 구조다.
- AdMate는 판단을 대신하지 않는다. 판단의 기준이 다음 업무에 재사용되게 만든다.
- AdMate는 기획, 검수, 증빙, 분석을 하나의 판단 근거 loop로 연결하는 운영 플랫폼이다.
- 임원 관점의 가치는 운영 품질, 감사 가능성, 통제 가능한 확장이다.

## 3. 메인 슬라이드 상세안

메인 슬라이드에는 "검증 필요", "임시 문안" 같은 제작 메모를 노출하지 않는다. 검증 메모는 appendix와 별도 fact-check 문서에만 둔다.

### 1. 왜 지금 AdMate인가

한 문장 메시지:

광고 운영의 병목은 업무량보다 판단 기준이 조직에 남지 않는 구조다.

보조 bullet:

- 브리프, 정책, 세팅, 증빙, 분석이 각자 따로 남는다.
- 담당자가 바뀌면 판단의 맥락도 함께 사라진다.
- 같은 확인이 다음 캠페인에서 반복된다.

발표자 노트:

오늘의 논점은 AI가 일을 얼마나 빨리 대신하느냐가 아닙니다. 광고 운영에서 더 큰 손실은 판단 기준이 조직 안에 남지 않는 구조입니다. 업무가 끝나도 왜 그렇게 판단했는지 남지 않으면 다음 캠페인은 다시 처음부터 시작됩니다.

시각 구성:

- 흩어진 업무 카드 5개를 좌우로 배치한다.
- 각 카드 사이의 연결선은 끊어진 형태로 표현한다.
- 실제 내부 화면 대신 추상화된 운영 흐름 다이어그램을 사용한다.

### 2. 문제는 기준의 소실이다

한 문장 메시지:

업무는 끝나도 근거가 남지 않으면 다음 판단은 다시 처음부터 시작된다.

보조 bullet:

- 결과 파일만으로는 판단 이유를 설명하기 어렵다.
- 정책 확인과 세팅 검토의 맥락이 분리된다.
- 보고와 회고가 다음 실행 기준으로 이어지지 않는다.

발표자 노트:

운영 결과가 남는 것과 판단 근거가 남는 것은 다릅니다. 어떤 정책을 확인했는지, 어떤 위험을 봤는지, 어떤 증빙을 남겼는지가 함께 남아야 다음 판단의 출발점이 됩니다.

시각 구성:

- 왼쪽은 "완료된 결과", 오른쪽은 "사라진 근거"로 대비한다.
- 하나의 중심 비교 그래픽만 사용한다.
- 수치나 실제 캠페인 사례는 넣지 않는다.

### 3. AdMate의 전환점

한 문장 메시지:

AdMate는 판단을 대신하지 않고 판단 근거가 재사용되도록 만든다.

보조 bullet:

- 최종 판단은 사람에게 남긴다.
- AI는 기준 탐색, 검토 흐름, 증빙 정리를 돕는다.
- 재사용 가능한 근거가 다음 업무의 출발점이 된다.

발표자 노트:

AdMate를 "판단하는 AI"로 설명하면 방향이 흔들립니다. v2의 핵심은 판단의 대체가 아니라 판단 근거의 보존입니다. 사람이 판단하고, AdMate는 그 판단에 쓰인 기준과 증빙이 다음 업무에서 다시 쓰이도록 돕습니다.

시각 구성:

- "AI decides"는 흐리게 처리하고 사용하지 않는 방향으로 표시한다.
- "People decide, AdMate preserves evidence" 의미의 전환 카드를 사용한다.
- 화면 문안은 한국어 중심으로 유지한다.

### 4. AdMate 운영 loop

한 문장 메시지:

기획, 검수, 증빙, 분석은 하나의 판단 근거 loop로 연결되어야 한다.

보조 bullet:

- 기획: 확인할 기준을 정한다.
- 검수: 위험 신호와 조치 상태를 본다.
- 증빙/분석: 결과와 다음 판단 가설을 남긴다.

발표자 노트:

AdMate의 운영 흐름은 단발성 자동화가 아니라 loop입니다. 기획에서 확인한 기준이 검수로 이어지고, 검수 결과가 증빙과 분석에 남고, 그 결과가 다음 캠페인의 검토 기준으로 돌아오는 구조입니다.

시각 구성:

- Plan, Review, Evidence, Learn 4단계 loop로 단순화한다.
- 각 단계 아래에 한국어 보조 라벨을 붙인다.
- 승인 게이트를 loop의 중앙 또는 하단에 표시한다.

### 5. 제품 역할 지도

한 문장 메시지:

각 제품은 기능이 아니라 업무 순간별 판단 근거를 맡는다.

보조 bullet:

- Compass: 기준 확인
- Sentinel: 위험 신호와 검토 기준
- Lens/Foresight: 증빙 흐름과 다음 판단 가설

발표자 노트:

제품을 기능 목록으로 나열하지 않겠습니다. 업무 순간으로 보면 더 명확합니다. Compass는 기준 확인, Sentinel은 위험 신호와 검토 기준, Lens는 증빙 흐름, Foresight는 다음 판단 가설, Agent Core와 Hermes는 승인과 기록, 학습 후보 관리에 가까운 역할로 설명할 수 있습니다.

시각 구성:

- 중앙에는 "판단 근거 loop"를 둔다.
- 주변에는 제품명을 업무 순간별 라벨로 배치한다.
- 제품별 세부 기능 설명은 appendix로 보낸다.

### 6. 기준 확인과 사전 검수

한 문장 메시지:

Compass와 Sentinel은 확인할 기준을 좁히고, 운영자가 봐야 할 위험 신호와 조치 필요 항목을 정리한다.

보조 bullet:

- Compass: 광고 정책, 상품, 심사 가이드의 근거를 찾아 검토 범위를 좁힌다.
- Sentinel Monitoring: 운영 중 이상 징후를 주기적으로 확인하는 흐름을 만든다.
- Sentinel Prelaunch: Google/Meta 중심 세팅과 미디어믹스 비교를 사전 검수한다.

발표자 노트:

Compass는 정책 판단을 자동 확정하는 도구가 아니라, 검토해야 할 근거를 찾아 범위를 좁히는 도구로 설명합니다. Sentinel은 실시간으로 모든 문제를 감지한다고 말하지 않습니다. 운영 중 또는 사전 검수 단계에서 이상 징후와 조치 필요 상태를 운영자가 볼 수 있게 하는 흐름으로 설명합니다.

시각 구성:

- 왼쪽은 기준 확인, 오른쪽은 사전 검수로 나눈다.
- Sentinel Monitoring과 Prelaunch Media Mix는 본문에서 한 장으로 묶는다.
- "승인 필요" 대신 "조치 필요", "운영자 검토" 라벨을 사용한다.

### 7. 증빙과 다음 판단 가설

한 문장 메시지:

Lens와 Foresight는 보고에 활용할 증빙과 다음 계획을 검토할 기준을 제공한다.

보조 bullet:

- Lens: 실제 매체 지면처럼 보이는 증빙 이미지와 캡처 정보를 정리한다.
- Foresight: 예측과 벤치마크 결과를 다음 캠페인 계획의 검토 기준으로 활용한다.
- 수치와 차트는 sanitized mock 또는 익명화된 집계 예시로만 제시한다.

발표자 노트:

Lens는 캡처 성공 여부보다 결과 이미지가 실제 매체 지면처럼 보이는지가 중요합니다. Foresight는 정확한 예측이나 최적 예산 추천을 약속하지 않습니다. 예측과 벤치마크를 다음 계획을 검토하는 기준으로 활용하는 방향으로 설명합니다.

시각 구성:

- 왼쪽에는 증빙 이미지 카드, 오른쪽에는 가설/벤치마크 카드
- 실제 광고주나 캠페인 수치는 사용하지 않는다.
- 수치가 필요하면 익명화된 집계 예시 또는 mock label을 표시한다.

### 8. Agent Core와 Hermes

한 문장 메시지:

실행 요청, 승인, 기록, 학습 후보는 같은 운영 기준 안에서 추적되어야 한다.

보조 bullet:

- Agent Core: 실행 요청, 승인, 기록이 추적되는 공통 레이어
- Audit trail: 누가, 어떤 기준으로, 어떤 조치를 검토했는지 남기는 흐름
- Hermes: 운영자 피드백과 검증된 이벤트에서 학습 후보를 만든다.

발표자 노트:

Agent Core와 Openclaw는 제품들을 완전히 연결 완료한 자동 실행 체계로 말하지 않습니다. 실행 요청, 승인, 기록, 학습 후보가 같은 운영 기준 안에서 추적되도록 하는 공통 레이어로 설명합니다. Hermes도 스스로 기준을 바꾸는 자동 학습이 아니라, 운영자 피드백과 검증된 이벤트를 바탕으로 학습 후보를 만들고 승인된 기준만 운영 지식으로 축적하는 방향으로 설명합니다.

시각 구성:

- 권한, 승인, 기록, 학습 후보 4개 블록
- 블록 사이를 승인 게이트와 audit trail 선으로 연결한다.
- "승인 없는 실행"처럼 보이는 자동화 화살표는 사용하지 않는다.

### 9. 임원 관점의 가치

한 문장 메시지:

AdMate의 가치는 운영 품질, 감사 가능성, 통제 가능한 확장에 있다.

보조 bullet:

- 운영 품질: 반복 검토의 기준을 조직에 남긴다.
- 감사 가능성: 판단과 조치의 맥락을 추적한다.
- 통제 가능한 확장: 승인된 기준만 다음 운영으로 확장한다.

발표자 노트:

임원 관점에서 중요한 것은 개별 기능의 많고 적음이 아닙니다. 기준이 남는 운영 품질, 누가 무엇을 왜 검토했는지 볼 수 있는 감사 가능성, 그리고 승인된 범위 안에서만 확장하는 통제 가능성이 핵심입니다.

시각 구성:

- 3개 가치 카드
- 각 카드에는 제목과 한 줄 설명만 넣는다.
- ROI나 성과 보장 수치 대신 파일럿 검증 지표 후보를 다음 장으로 넘긴다.

### 10. 파일럿 제안

한 문장 메시지:

작은 범위에서 시작하고 검증된 기준만 다음 단계로 확장한다.

보조 bullet:

- 범위: Google/Meta 중심의 제한된 업무 흐름
- 검증 지표: 기준 재사용, 반복 검토 항목 감소 여부, 증빙 품질
- 승인 기준: 운영자 검토와 Commander 승인

발표자 노트:

v2의 실행 제안은 작게 시작하는 것입니다. 모든 제품을 한 번에 완성형으로 보여주기보다, Google/Meta 중심의 제한된 업무 흐름에서 기준 확인, 사전 검수, 증빙, 다음 판단 가설까지 이어지는지 봅니다. 검증된 기준만 다음 단계로 확장합니다.

시각 구성:

| 범위 | 검증 지표 | 승인 기준 |
|---|---|---|
| Google/Meta 중심 제한 파일럿 | 기준 재사용 여부, 반복 검토 항목 감소 여부, 증빙 이미지 품질 | 운영자 검토, Commander 승인, 보안/브랜드 체크 |

## 4. Appendix A: 제품별 표현 기준

이 appendix는 제작팀과 Commander 검토용이다. 메인 슬라이드에는 세부 검증 메모를 노출하지 않는다.

### Compass

사용 방향:

- 광고 정책, 상품, 심사 가이드의 근거를 찾아 검토 범위를 좁히는 도구
- 정책 판단을 확정하는 것이 아니라, 사람이 볼 근거와 출처를 정리하는 역할
- 검토 시작점의 혼선을 줄이는 역할

금지 표현:

- 정책 판단 자동 확정
- 심사 통과 보장
- 정책 리스크 제거
- 모든 정책 완벽 반영

### Sentinel Monitoring

사용 방향:

- 운영 중 또는 주기적 모니터링을 통해 이상 징후 확인 흐름을 만든다.
- "승인 필요"보다 "조치 필요", "운영자가 검토할 항목"을 사용한다.
- 모든 순간을 즉시 감지한다는 표현보다 운영 검토 흐름을 강조한다.

금지 표현:

- 실시간으로 항상 감지
- 즉시 차단
- 모든 위험 자동 발견
- 승인 없는 조치 실행

### Sentinel Prelaunch Media Mix Review

사용 방향:

- "Sentinel Media Mix"라는 독립 제품처럼 부르지 않는다.
- Sentinel Prelaunch의 미디어믹스 비교/사전 검수 기능으로 설명한다.
- Google/Meta 중심의 세팅 검수와 비교 흐름으로 표현한다.

금지 표현:

- 최적 미디어믹스 추천
- 예산 배분 추천
- 모든 매체 지원
- 자동 플래닝 확정

### Lens

사용 방향:

- 검토와 보고에 활용할 수 있는 증빙 이미지와 캡처 정보를 정리한다.
- 핵심 품질 기준은 캡처 성공 여부보다 결과 이미지가 실제 매체 지면처럼 보이는지다.
- 실제 화면 대신 sanitized mock visual 또는 승인된 예시만 사용한다.

금지 표현:

- 재사용 가능한 evidence package
- 모든 지면 완벽 재현
- 실제 광고주 화면 무제한 사용
- 캡처만 성공하면 품질 완료

### Foresight

사용 방향:

- 예측과 벤치마크 결과를 다음 캠페인 계획의 검토 기준으로 활용한다.
- 성과 보장이 아니라 판단 가설과 검토 관점으로 설명한다.
- 수치/차트는 sanitized mock 또는 익명화된 집계 예시라고 명시한다.

금지 표현:

- 성과 보장
- 최적 예산 추천
- 정확한 예측
- 자동 의사결정

### Agent Core / Openclaw

사용 방향:

- 실행 요청, 승인, 기록, 학습 후보가 같은 운영 기준 안에서 추적되도록 하는 공통 레이어
- 승인 게이트와 audit trail을 중심으로 설명한다.
- 완성된 end-to-end 자동화보다 통제 가능한 운영 구조를 강조한다.
- Openclaw는 메인 슬라이드에서 병기하지 않고, Agent Core 내부의 실행/자동화 흐름으로 설명한다.

금지 표현:

- 제품들을 완전한 loop로 연결 완료
- 완전 자동 집행
- 승인 없는 실행
- 모든 작업 자동 orchestration

### Hermes

사용 방향:

- 운영자 피드백과 검증된 이벤트를 바탕으로 학습 후보를 만든다.
- 승인된 기준만 운영 지식으로 축적한다.
- 학습 후보와 검토된 기준 축적의 흐름으로 설명한다.

금지 표현:

- 자동 학습
- 스스로 판단
- 즉시 기준 변경
- 검토 없는 운영 지식 반영

## 6. Appendix C: 안전 고지와 제작 기준

메인 슬라이드에는 필요한 안전 고지만 자연스럽게 포함하고, 제작 메모처럼 보이는 문장은 넣지 않는다.

권장 고지:

- 본 발표의 화면 예시는 sanitized mock visual 또는 익명화된 집계 예시 기준입니다.
- 최종 판단과 승인 권한은 사람에게 있습니다.
- AI presenter 사용 시 실제 인물이 아닌 가상 브랜드 캐릭터로만 사용합니다.
- 예측과 벤치마크는 성과 보장이 아니라 다음 계획의 검토 기준입니다.

제작 기준:

- 한 슬라이드에는 한 문장 메시지 1개만 둔다.
- 보조 bullet은 최대 3개로 제한한다.
- 시각 요소는 슬라이드당 1개 중심으로 구성한다.
- 실제 내부 화면, 광고주명, 캠페인명, 계정 정보, 예산, 성과 지표, 개인정보는 사용하지 않는다.

Commander 검증 의견을 반영해 표현을 완화했다. 아래 문장은 최종 슬라이드 제작 전 플랫폼 표현과 제작 톤을 한 번 더 맞추기 위한 확인 문장이다.

- Compass: "광고 정책, 상품, 심사 가이드의 근거를 찾아 검토 범위를 좁힌다."
- Sentinel Monitoring: "운영 중 이상 징후를 주기적으로 확인하는 흐름을 만든다."
- Sentinel Prelaunch: "Google/Meta 중심 세팅과 미디어믹스 비교를 사전 검수한다."
- Lens: "결과 이미지가 실제 매체 지면처럼 보이는지가 핵심 품질 기준이다."
- Foresight: "예측과 벤치마크 결과를 다음 캠페인 계획의 검토 기준으로 활용한다."
