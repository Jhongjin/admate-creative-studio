# AdMate 발표자료 v2 슬라이드 제작 스펙

대상 deck: AdMate 임원 보고용 10장 v2
목적: PPTX 또는 Google Slides 제작 전, 슬라이드별 메시지, 원고, 발표자 노트, 시각자료 타입, 데이터 민감도를 고정한다.
제작 원칙: 실제 AdMate UI와 demo/mock/anonymized data를 우선 사용하되, 민감정보는 노출하지 않는다.

## 1. 공통 제작 기준

- 한 슬라이드에는 한 문장 메시지 1개만 둔다.
- 본문 bullet은 최대 3개로 제한한다.
- 시각 요소는 슬라이드당 1개 중심으로 구성한다.
- 메인 메시지는 "AI 자동화"가 아니라 "판단 근거 보존과 통제 가능한 운영 확장"이다.
- 실제 제품 UI는 가능한 경우 우선 사용하되, 기본값은 `실제 UI + demo/mock/anonymized data`다.
- 실제 광고주명, 캠페인명, 예산, 성과 수치를 쓰는 슬라이드는 `restricted real case 후보`로 별도 표시하고 Commander 확인을 받는다.
- 계정 ID, email, token, API key, 매체 계정 식별자, 개인정보는 내부용이어도 노출하지 않는다.
- 외부 공유 가능성을 고려해 실명 버전과 익명화 버전을 분리 제작할 수 있게 설계한다.

## 3. 슬라이드별 제작 스펙

### 1. 왜 지금 AdMate인가

한 문장 메시지:

광고 운영의 병목은 업무량보다 판단 기준이 조직에 남지 않는 구조다.

본문 bullet:

- 브리프, 정책, 세팅, 증빙, 분석이 따로 남는다.
- 담당자가 바뀌면 판단 맥락도 함께 사라진다.
- 같은 확인이 다음 캠페인에서 반복된다.

발표자 노트:

오늘의 논점은 AI가 일을 얼마나 빨리 대신하느냐가 아닙니다. 광고 운영에서 더 큰 손실은 판단 기준이 조직 안에 남지 않는 구조입니다. 업무가 끝나도 왜 그렇게 판단했는지 남지 않으면 다음 캠페인은 다시 처음부터 시작됩니다.

시각 요소:

흩어진 운영 흐름 다이어그램. 브리프, 정책, 세팅, 증빙, 분석 카드가 서로 끊어진 구조로 보이게 한다.

디자인 지시:

타이포 중심의 오프닝으로 구성한다. 배경은 차분한 다크 또는 페이퍼 톤을 사용하고, 제품 UI는 아직 노출하지 않는다.

시각자료 타입: `diagram`
데이터 민감도 등급: `public_mock`

### 2. 문제는 기준의 소실이다

한 문장 메시지:

업무는 끝나도 근거가 남지 않으면 다음 판단은 다시 처음부터 시작된다.

본문 bullet:

- 결과 파일만으로는 판단 이유를 설명하기 어렵다.
- 정책 확인과 세팅 검토의 맥락이 분리된다.
- 보고와 회고가 다음 실행 기준으로 이어지지 않는다.

발표자 노트:

운영 결과가 남는 것과 판단 근거가 남는 것은 다릅니다. 어떤 정책을 확인했는지, 어떤 위험을 봤는지, 어떤 증빙을 남겼는지가 함께 남아야 다음 판단의 출발점이 됩니다.

시각 요소:

결과와 근거의 분리 비교. 왼쪽에는 완료된 결과, 오른쪽에는 사라진 근거를 배치한다.

디자인 지시:

한 화면에 하나의 비교 그래픽만 둔다. 실제 캠페인 사례나 수치는 사용하지 않는다.

시각자료 타입: `diagram`
데이터 민감도 등급: `public_mock`

### 3. AdMate의 전환점

한 문장 메시지:

AdMate는 판단을 대신하지 않고 판단 근거가 재사용되도록 만든다.

본문 bullet:

- 최종 판단은 사람에게 남긴다.
- AI는 기준 탐색, 검토 흐름, 증빙 정리를 돕는다.
- 남은 근거가 다음 업무의 출발점이 된다.

발표자 노트:

AdMate를 판단하는 AI로 설명하면 방향이 흔들립니다. 핵심은 판단의 대체가 아니라 판단 근거의 보존입니다. 사람이 판단하고, AdMate는 그 판단에 쓰인 기준과 증빙이 다음 업무에서 다시 쓰이도록 돕습니다.

시각 요소:

대체 vs 보존 전환 카드. "AI decides" 방향은 사용하지 않고, "사람 판단 + AdMate 근거 보존" 구조를 보여준다.

디자인 지시:

대비형 카드 2개를 사용하되, 부정 항목은 작게 처리하고 긍정 메시지를 크게 둔다.

시각자료 타입: `diagram`
데이터 민감도 등급: `public_mock`

### 4. AdMate 운영 loop

한 문장 메시지:

기획, 검수, 증빙, 분석은 하나의 판단 근거 loop로 연결되어야 한다.

본문 bullet:

- 기획: 확인할 기준을 정한다.
- 검수: 위험 신호와 조치 상태를 본다.
- 증빙/분석: 결과와 다음 판단 가설을 남긴다.

발표자 노트:

AdMate의 운영 흐름은 단발성 자동화가 아니라 loop입니다. 기획에서 확인한 기준이 검수로 이어지고, 검수 결과가 증빙과 분석에 남고, 그 결과가 다음 캠페인의 검토 기준으로 돌아오는 구조입니다.

시각 요소:

기획, 검수, 증빙, 기준 축적 4단계 운영 loop.

디자인 지시:

중앙에는 승인 게이트를 배치한다. 자동 실행처럼 보이는 직선 화살표보다, 사람이 확인하는 순환 구조를 강조한다.

시각자료 타입: `diagram`
데이터 민감도 등급: `public_mock`

### 5. 제품 역할 지도

한 문장 메시지:

각 제품은 기능이 아니라 업무 순간별 판단 근거를 맡는다.

본문 bullet:

- Compass: 기준 확인
- Sentinel: 위험 신호와 검토 기준
- Lens/Foresight: 증빙 흐름과 다음 판단 가설

발표자 노트:

제품을 기능 목록으로 나열하지 않겠습니다. 업무 순간으로 보면 더 명확합니다. Compass는 기준 확인, Sentinel은 위험 신호와 검토 기준, Lens는 증빙 흐름, Foresight는 다음 판단 가설, Agent Core와 Hermes는 승인과 기록, 학습 후보 관리에 가까운 역할로 설명할 수 있습니다.

시각 요소:

중앙에 판단 근거 loop를 두고, 주변에 제품을 업무 순간별로 배치한 역할 지도.

디자인 지시:

제품 로고나 이름이 과도하게 많아 보이지 않게 한다. 라벨은 업무 순간 중심으로 짧게 쓴다.

시각자료 타입: `diagram`
데이터 민감도 등급: `public_mock`

### 6. 기준 확인과 사전 검수

한 문장 메시지:

Compass와 Sentinel은 확인할 기준을 좁히고, 운영자가 봐야 할 위험 신호와 조치 필요 항목을 정리한다.

본문 bullet:

- Compass: 정책·상품·심사 가이드 근거를 찾아 검토 범위를 좁힌다.
- Sentinel Monitoring: 운영 중 이상 징후를 주기적으로 확인한다.
- Sentinel Prelaunch: Google/Meta 중심 세팅과 미디어믹스 비교를 사전 검수한다.

발표자 노트:

Compass는 정책 판단을 자동 확정하는 도구가 아니라, 검토해야 할 근거를 찾아 범위를 좁히는 도구로 설명합니다. Sentinel은 모든 문제를 즉시 감지한다고 말하지 않습니다. 운영 중 또는 사전 검수 단계에서 이상 징후와 조치 필요 항목을 운영자가 볼 수 있게 하는 흐름으로 설명합니다.

시각 요소:

Compass 답변 화면과 Sentinel 조치 필요 항목 화면을 하나의 "기준 확인/사전 검수" 흐름으로 묶은 실제 UI 캡처 합성.

디자인 지시:

실제 AdMate UI를 우선 사용한다. 데이터는 demo 또는 anonymized로 처리하고, 광고주명, 캠페인명, 계정 식별자는 보이지 않게 한다.

시각자료 타입: `real_admate_ui_demo_data`
데이터 민감도 등급: `internal_anonymized`

### 7. 증빙과 다음 판단 가설

한 문장 메시지:

Lens와 Foresight는 보고에 활용할 증빙과 다음 계획을 검토할 기준을 제공한다.

본문 bullet:

- Lens: 매체 지면처럼 보이는 증빙 이미지와 캡처 정보를 정리한다.
- Foresight: 예측과 벤치마크를 다음 계획의 검토 기준으로 제공한다.
- 수치와 차트는 익명화된 집계 예시 또는 sanitized mock으로 제시한다.

발표자 노트:

Lens는 캡처 성공 여부보다 결과 이미지가 실제 매체 지면처럼 보이는지가 중요합니다. Foresight는 정확한 예측이나 최적 예산 추천을 약속하지 않습니다. 예측과 벤치마크를 다음 계획을 검토하는 기준으로 활용하는 방향으로 설명합니다.

시각 요소:

Lens synthetic output 카드와 Foresight benchmark/forecast 카드가 나란히 보이는 실제 UI 또는 승인된 샘플 합성.

디자인 지시:

외부 매체 화면은 실제 운영 계정 캡처가 아니라 Lens synthetic output 또는 승인된 샘플 이미지를 우선 사용한다. Foresight 수치는 익명화된 집계 또는 sanitized mock으로 표기한다.

시각자료 타입: `lens_synthetic_sample`
데이터 민감도 등급: `internal_anonymized`

### 8. Agent Core와 Hermes

한 문장 메시지:

실행 요청, 승인, 기록, 학습 후보는 같은 운영 기준 안에서 추적되어야 한다.

본문 bullet:

- Agent Core: 실행 요청, 승인, 기록이 추적되는 공통 레이어
- Audit trail: 누가, 어떤 기준으로, 어떤 조치를 검토했는지 남긴다.
- Hermes: 운영자 피드백과 검증된 이벤트에서 학습 후보를 만든다.

발표자 노트:

Agent Core는 제품들을 완전히 연결 완료한 자동 실행 체계로 말하지 않습니다. 실행 요청, 승인, 기록이 같은 운영 기준 안에서 추적되도록 하는 공통 운영 레이어로 설명합니다. Hermes도 스스로 기준을 바꾸는 자동 학습이 아니라, 운영자 피드백과 검증된 이벤트를 바탕으로 학습 후보를 만들고 승인된 기준만 운영 지식으로 축적하는 방향으로 설명합니다.

시각 요소:

권한, 승인, 기록, 학습 후보 4개 블록을 승인 게이트와 audit trail 선으로 연결한 다이어그램. 가능하면 Slack Ops 알림/승인 흐름의 마스킹된 실제 화면을 작은 보조 패널로 포함한다.

디자인 지시:

메인 표기는 Agent Core와 Hermes만 사용한다. Openclaw는 발표자 노트나 appendix에서 Agent Core 내부 실행/자동화 흐름으로 설명한다.

시각자료 타입: `diagram`
데이터 민감도 등급: `internal_anonymized`

### 9. 임원 관점의 가치

한 문장 메시지:

AdMate의 가치는 운영 품질, 감사 가능성, 통제 가능한 확장에 있다.

본문 bullet:

- 운영 품질: 반복 검토의 기준을 조직에 남긴다.
- 감사 가능성: 판단과 조치의 맥락을 추적한다.
- 통제 가능한 확장: 승인된 기준만 다음 운영으로 확장한다.

발표자 노트:

임원 관점에서 중요한 것은 개별 기능의 많고 적음이 아닙니다. 기준이 남는 운영 품질, 누가 무엇을 왜 검토했는지 볼 수 있는 감사 가능성, 그리고 승인된 범위 안에서만 확장하는 통제 가능성이 핵심입니다.

시각 요소:

운영 품질, 감사 가능성, 통제 가능한 확장 3요소 카드.

디자인 지시:

정량 성과 수치보다 경영 판단 프레임을 강조한다. 실제 광고주 사례가 필요하면 별도 restricted 후보로 분리한다.

시각자료 타입: `diagram`
데이터 민감도 등급: `public_mock`

### 10. 파일럿 제안

한 문장 메시지:

작은 범위에서 시작하고 검증된 기준만 다음 단계로 확장한다.

본문 bullet:

- 범위: Google/Meta 중심의 제한된 업무 흐름
- 검증 지표: 기준 재사용, 반복 검토 항목 감소 여부, 증빙 품질
- 승인 기준: 운영자 검토와 Commander 승인

발표자 노트:

실행 제안은 작게 시작하는 것입니다. 모든 제품을 한 번에 완성형으로 보여주기보다, Google/Meta 중심의 제한된 업무 흐름에서 기준 확인, 사전 검수, 증빙, 다음 판단 가설까지 이어지는지 봅니다. 검증된 기준만 다음 단계로 확장합니다.

시각 요소:

범위, 검증 지표, 승인 기준 3열 파일럿 결정표.

디자인 지시:

결정표는 넓고 단순하게 구성한다. "효과 달성"이 아니라 "검증 여부"가 보이도록 표현한다.

시각자료 타입: `decision_table`
데이터 민감도 등급: `internal_anonymized`
